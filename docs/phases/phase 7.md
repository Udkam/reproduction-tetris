# Phase 7：50 关 Puzzle 课程

## 状态与回退基线

**合同已打开，产品源码尚未打开。** Phase 6 已验收并推送；Phase 7 从干净、
远端一致的恢复记录 `d78e0e580ceb9375afb57fc8c4230624e4a54a77` 开始。
现有选关页的视觉构图冻结，只允许适配 50 关数据、内部滚动、解锁状态、名称和
既有纪录，不得换成新的页面设计。

## 目标

把现有 20 关重编并扩展为 50 个可求解、确定性、逐步教学且不依赖反常识唯一解
的残局。每关先教授或复用一个明确的堆叠概念，再组合已学概念；它不是随机堆积、
只换颜色或把穷举结果伪装成设计。

50 关使用稳定的关卡顺序和固定输入序列。旧 20 个内部 ID 保持稳定并占据当前
对应序号，新增关卡使用 `tm-puzzle-21` 至 `tm-puzzle-50`。玩家可见名称使用
简洁的结构性名称：中文 2–4 字，英文 1–2 个词；禁止无从理解的长诗意名称、
技术代号和重复解释。

## 课程与初始棋盘

| 关卡 | 原有方块行数 | 教学重点 |
| --- | ---: | --- |
| 01–10 | 3 | 平面补洞、边缘落点、转向、简单双消 |
| 11–20 | 4 | 井、平台、悬挑恢复、顺序选择 |
| 21–30 | 5 | 延迟满足、连续清行、局部取舍 |
| 31–40 | 6 | 锚点绕行、共享落点、恢复空间 |
| 41–50 | 7 | 多阶段组合、备选路线、综合收束 |

- 初始普通方块必须来自合法、确定性的空盘硬降历史；历史中不允许消行、隐藏区
  残留、非法出生或同色来源块错误融合。
- 每关的 `targetRows` 是显式数据，不再从 `difficulty` 或 UI band 下标推断。
  原有目标必须占据贴底且连续的恰好 3–7 行，每行开局都不能已经填满。
- 合法 setup 数量按棋盘需要放宽为 5–15 块；每块仍完整贡献四个原有目标格。
- 经典、生存、异变继续每局使用新的随机七袋；Puzzle 的普通七袋由关卡 seed
  固定，重开和撤回不能改变后续序列。

## 不可消锚点

锚点是稀疏、关卡作者确定的空间约束，不是运行时随机障碍：

- 01–10、11–20、21–30、31–40、41–50 分别安排 1、2、3、3、4 个带锚点关卡；
  每个带锚点关卡通常只有一个锚点，最后十关至多两关可使用两个。
- 前五关不出现锚点。锚点只能位于原有目标带正上方的可见空行，不能占据任何
  初始方块行、原有目标格或隐藏区。
- 锚点坐标永久固定、不可消、不是胜利目标；普通消行不得使其下移，也不得让
  其他方块穿过锚点。
- 开局和两条验收路线都不得依赖“包含锚点的十格满行”作为解题步骤。每个带
  锚点关卡必须由 Core 重放证明锚点不会封死目标或制造异常掉落。
- 不恢复已经删除的限时消失方块。

## 冻结玩法

- 胜利只要求清除全部原有目标方块；没有公开方块数上限。
- `Z` 立即回到上一个方块尚未出现的规范快照，并重新开始该方块的下落；不弹
  确认框。
- Next 继续在同一个既有深色框内显示完整的 `1`（下一个）和 `2`（后一个）。
- 不恢复难懂提示，也不生成 Solution 图片或玩家可见路线文档。
- “操作数 / 当前最优步数”统一指成功锁定的四格方块数，不是键盘、触控或 tick
  命令数。

## 渐进解锁

解锁集合只由规范完成历史计算，不持久化一个可过期的 `unlockedLevelIds`：

1. 新存档开放 `01–03`。
2. `01–03` 任意完成 2 关，开放 `04–05`。
3. `01–05` 任意完成 3 关，开放 `06–10`。
4. 此后每个五关组任意完成 3 关，开放下一个五关组：
   `06–10 → 11–15 → … → 46–50`。

解锁按前沿递归计算；旧记录中越级完成的关卡本身始终可重玩，但在前置组尚未
开放时不能越级解锁其后续组。锁定关卡可见但不可选择、开始或写入完成记录。
选关页和设置规则使用一句精炼中英文写清当前条件，不增加说明墙。

## 求解、难度与路线证据

每关必须有两条由当前公开 Core `dispatch()` 全程重放成功的路线：

- 两条路线都从正式关卡 seed、setup 和 Next 序列开始，以清空全部原有目标结束；
- 它们必须在不晚于较短路线前四次锁定内出现不同的规范落点，不能只是最后一步
  换序或左右镜像 token；
- 记录锁定数、旋转数、横移量、清行分布、最大高度、空洞、分支宽度、首次分歧
  和锚点负担；
- 同一十关批次先按行数固定，再依据上述指标和人工可读性排序；不把 beam
  search 找到的路线宣称为数学最优；
- 生成器只产出候选。最终定义、双路线和指标写入新的 Phase-7 source-bound
  artifact，测试只重放已选路线；普通测试不得每次重新穷举 50 关。

求解批处理一次只运行一个十关 batch，不与完整测试、构建或浏览器自动化叠加。
每批在开始下一批前独立求解、复核、命名、提交并留下回退点。

## 资源边界

使用 2026-07-30 更新后的动态资源预算，而不是旧的固定强串行限制：

- 绿档（CPU <70%、可用内存 ≥12 GB、磁盘队列 <1）：本对话最多四个智能体，
  但共享路径仍只有一个 writer，最多两个重任务同时运行；
- 黄档（CPU 70–89%、可用内存 8–12 GB 或磁盘队列 1–2）：最多两个智能体，
  不再启动新的求解、构建、浏览器或 GPU 重任务；
- 红档（CPU ≥90%、可用内存 <8 GB 或磁盘队列 >2）：不启动新重任务，只按
  已验证的项目/父子树/命令/端口所有权收束当前资源。

Serena、MCP、Node、浏览器、开发服务器和求解进程都只按当前 slice 启动，在
阶段边界按所有权回收；不使用 WMI/CIM，不按进程名或端口猜测并结束进程。
