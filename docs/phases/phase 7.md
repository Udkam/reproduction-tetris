# Phase 7：50 关 Puzzle 课程

## 状态

待 Phase 6 验收并推送后开始。现有选关页的视觉构图明确冻结，只允许适配 50 关
数据、滚动、解锁和既有信息。

## 目标

把 20 关扩展为 50 个可求解、确定性、逐步教学且不过度唯一解的残局。关卡不是
随机堆积或只换颜色；每关要有明确的俄罗斯方块思想，先教一个概念，再组合已学
概念，并尽可能允许两条以上合理路线。

## 课程分批

1. **01–10 基础落点**：3 行为主，教授平面补洞、边缘、转向、简单双消。
2. **11–20 井与悬挑**：3–4 行，教授井深、平台、过hang恢复和顺序选择。
3. **21–30 序列与多消**：4–5 行，固定队列、延迟满足、连续清行和局部取舍。
4. **31–40 锚点路线**：5–6 行，稀疏不可消锚点，教授绕行和共享落点；锚点不得
   直接把目标行封成无解，也不计入胜利目标。
5. **41–50 综合残局**：6–7 行，组合前述概念、多个阶段和备选路线；难度上升但
   不依赖不可见提示、超长穷举或反常识唯一落子。

每批十关在进入下一批前独立求解、排序、命名、提交和审计。

## 冻结玩法

- 胜利只要求清除全部原有目标方块；没有公开方块数上限。
- 方块序列固定；经典、生存、异变仍是每局随机。
- `Z` 直接回到上一方块尚未出现、随后开始下落的规范快照。
- 不恢复当前已移除的难懂提示，也不自动生成 Solution 图片/文档。
- 记录当前关最少操作数；通关与解锁条件必须用精炼中英文写清。
- 锚点坐标固定、不可消、非目标；任何行清除后都不得因普通重力错误位移。

## 可回退团队

1. `t15_puzzle_schema_writer`：50 关 ID、版本、迁移和解锁合同。
2. 五个顺序 batch writer：01–10、11–20、21–30、31–40、41–50。
3. `t15_puzzle_progress_ui_writer`：进度、最少步数、50 关适配；不重设选关构图。
4. `t15_puzzle_rules_qa`：Core replay、求解、锚点、撤回、迁移和解锁。
5. `t15_puzzle_visual_qa`：棋盘可读性、Next 两块、50 关现有构图适配。
6. `t15_puzzle_evidence_qa`：50 关路线、难度排序和候选产物来源。

## 关卡验收

每关至少有一条由当前 Core `dispatch()` 全程重放成功的权威路线；适合多解的关卡
增加第二条不同策略路线验证。批次内按求解深度、分支宽度、旋转/移动复杂度、
锚点负担和恢复余量排序，而非按文件顺序主观排序。迁移保留原 20 关合法进度，
无越权解锁或丢失最少步数。最终对 50 关运行完整 solver/replay、类型检查、全套
测试、构建和浏览器适配证据。
