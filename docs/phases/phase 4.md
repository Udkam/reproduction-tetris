## 目标

把上升基岩与独立落石整理为一个可预测、可读且公平的压力系统。玩家应能判断
下一次威胁何时发生、来自哪里，并理解落石既可能阻碍也可能协助消行。

## 冻结规则

- 开局三层棕色基岩；不再尝试石头纹理或不规则轮廓。
- 基岩周期从 13 秒逐步缩短到 6 秒；每消 3 行移除一层。
- 独立落石周期从 20 秒逐次减 1 到 10 秒；每次 1–2 枚。
- 每次落石前 2 个有效游玩秒由 Core 预选 1–2 个唯一列；预警列与实际生成
  共用同一 canonical plan。到期时若所有预警入口均被占用，事件保持到期并
  持续预警，直到至少一列可生成；不得静默跳过或换到未预警列。
- 落石速度约为普通方块下落速度的 1.5 倍，独立更新，可参与消行和得分。
- 生存普通方块保持既定固定速度；随机七袋与落石随机源必须隔离且可重放。
- 排行只记录/显示生存时间、消行数和日期，不显示方块数。
- HUD 保持四格：生存时间、消行、带当前层数的基岩上升时钟、落石时钟；
  不新增第五张空位卡。

## 实现阶段

1. `survival-core`：只补 canonical 两秒预警计划、阻塞延后和确定性测试；
   现有计时、消行、RNG 隔离与固定速度不重写。
2. `survival-render`：保留现有棕色基岩/灰蓝落石材质，加入列预警、按 id
   的格间插值、局部进入/落地反馈和 reduced-motion 静态端点。
3. `survival-ui`：四格压力 HUD 与共享紧急状态，不增加长说明。
4. `survival-records`：升级 mode-discriminated v8；生存 JSON 仅保留时间、
   消行、日期和必要 schema 元数据，v7 迁移明确丢弃 score/pieces/chain。
5. `candidate/evidence`：长时运行、边界消行、顶出、重启/卸载资源验证。

每个检查点独立提交，不把 Core、Renderer 和 UI 压成一个无法回退的 commit。
