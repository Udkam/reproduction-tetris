## 目标

让唯一 Pixi 棋盘成为四种模式共同的视觉中心。顶部栏、统计、状态与 Next 使用
同一套稳定的几何和信息层级，不再因模式、语言或视口切换而跳位、消失或留下
结构性空白。键盘、鼠标和真实触控都必须直接命中同一局面，3 → 2 → 1 倒计时
必须覆盖棋盘且不改变布局。

## 已确认的基线问题

1. 桌面端四模式的右栏起始高度不同；Mutation 与 Puzzle 会把统计和 Next 推到
   与 Classic/Survival 不同的位置。
2. 390 × 844 下 Classic/Survival 的右栏被隐藏，Mutation 只剩状态，Puzzle 又
   使用独立高度；棋盘起点和尺寸随模式跳变。
3. 844 × 390 下 Next 被压得过窄，外层浅色区域却保留大块无效空间。
4. 出生区只绘出进入可见行的部分，形成方块像从棋盘外伸出的错误剪影。
5. 真实触控命中的是位于交互层上方的 Canvas，当前 `board-frame` 手势处理没有
   收到点击；该问题必须以真实 touch context 复验，不能只靠 jsdom。

## 冻结目标

### 1. 共享几何

- 桌面端棋盘与右栏共用同一顶部和纵向轴；棋盘保持 1:2，并继续占据主要视觉
  面积。右栏内部依次为统计、可选模式状态、Next，未激活的状态不制造空卡。
- 竖屏端四模式共用一个固定高度的信息带，再接同一尺寸棋盘。统计和 Next 始终
  可见；Mutation 状态只在信息带内增量展开，不得再次隐藏统计或预览。
- 短横屏端使用紧凑的棋盘 + 右栏组合，Next 保留可辨识的单元格尺寸；不得为已
  移除的键盘说明预留空行。
- 同一视口切换模式时，棋盘边界误差不超过 1 px；倒计时蒙版边界必须与棋盘
  完全重合。

### 2. 统计与文字

- Classic/Mutation 使用 `下落速度/格` / `Fall speed / cell`。
- Puzzle 使用 `操作数` / `Moves`，并保留原有方块剩余数。
- Survival 保留分数、消行、基岩和下一次上升；本阶段不修改压力规则。
- 数值使用 JetBrains Mono，标题和说明使用设计系统 UI 字体；不得以缩小到
  12 px 以下来换取布局通过。

### 3. Next

- Classic、Survival、Mutation 使用一个普通深色 Next 井。
- Puzzle 仍使用一个同样的深色井，但分成上下两行；左侧以清晰、完整的
  JetBrains Mono `1`、`2` 标识下一个和后一个方块。
- 每个预览的可访问名称必须包含序位和实际方块类型；Mutation 后续在 Phase 5
  追加附件身份，本阶段只保留可扩展语义。
- ready 倒计时期间可以保留空井；进入 playing 后必须显示正确队列。

### 4. 出生表现和输入

- Core 出生坐标、碰撞和随机序列不变；仅允许 presentation 层把部分隐藏的活动
  方块完整呈现在可见井口，再自然回到 Core 位置。
- 交互覆盖层位于 Canvas 之上但完全透明，只覆盖棋盘边界；鼠标点击负责聚焦，
  触控点击/滑动负责旋转、移动和下落。
- 倒计时期间输入保持禁用；倒计时、Settings、Pause、Restart 的既有冻结/恢复
  生命周期不变。
- 棋盘只保留一个可访问主名称；倒计时继续使用 live status，不制造重复朗读。

## 验收矩阵

四模式至少覆盖 1440 × 900、390 × 844、844 × 390、1056 × 480 和 reduced
motion。候选必须同时证明：

- 3、2、1 三个可见状态与 playing 状态；
- 四模式同视口棋盘几何稳定，统计和 Next 无遮挡或隐藏；
- Puzzle `1`、`2` 完整且与两个真实预览一一对应；
- 出生方块完整位于棋盘，Next 与棋盘方块不裁切；
- 真实 touch context 的点击、横滑、下滑和取消路径可用；
- 一个 Canvas、零 DOM 方格、零横向溢出、零控制台/page error；
- 中英文、44 px 命中区、reduced-motion 静态终态和卸载资源均通过。

只有规则 QA 与视觉 QA 接受同一候选、资源释放、日志更新并非强制推送完成后，
Phase 3 才能标记完成并向 Phase 4 交接。
